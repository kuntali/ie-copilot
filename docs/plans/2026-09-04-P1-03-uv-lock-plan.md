# P1-03 — uv.lock 与可重复依赖安装计划

**Task:** `P1-03`  
**Method:** Superpowers `writing-plans` + `verification-before-completion`  
**Status:** execution in progress  
**Live status:** `docs/TASKS.md`

## Goal

为当前 Python 3.10+ 项目生成并提交真实的 `uv.lock`，并让 CI 使用 lockfile 做 frozen/reproducible install，避免每次 CI 都按宽松版本范围重新解析依赖。

## Constraints

- 不手工编造或编辑 resolver 生成的 lockfile；
- 不为了生成 lockfile 放宽/删除现有依赖；
- Python 3.10 是必须验证的基线，3.13 保留兼容矩阵；
- unit test 仍不得依赖外部 API；
- 若本地环境无法访问包索引，可使用有网络的受控 CI 生成候选 lock artifact，但最终提交前必须验证该 lockfile 与 `pyproject.toml` 一致；
- 不在本任务顺手修 Ruff/测试行为问题，除非它阻止 lockfile 验证本身。

## Files

- `pyproject.toml` — 依赖声明源；除非 resolver 明确暴露依赖约束冲突，否则本任务不改版本策略。
- `uv.lock` — 由 uv resolver 生成并提交。
- `.github/workflows/ci.yml` — lockfile 存在后将安装切换为 frozen 模式。
- `docs/TASKS.md` — 动态状态和证据。

## Steps

1. **Baseline inspection**
   - 确认 `uv.lock` 当前不存在；
   - 读取 `pyproject.toml` 与 CI 安装命令；
   - 记录当前 CI run 已证明 Python 3.10 能完成非 frozen `uv sync`。

2. **Generate lockfile**
   - 首选在隔离开发环境执行 `uv lock`；
   - 若因网络/DNS 阻塞无法解析，记录错误证据，不手写 lockfile；
   - 必要时使用 GitHub Actions 的联网 runner 执行 `uv lock` 并产出 artifact，下载后提交。

3. **Verify lockfile**
   - `uv lock --check` 或等价检查必须通过；
   - Python 3.10 执行 `uv sync --frozen --extra dev --python 3.10`；
   - 若项目元数据变化导致 lock stale，应失败而不是自动重写。

4. **Make CI reproducible**
   - 将 `.github/workflows/ci.yml` 的安装步骤切换到 frozen 模式，例如：
     `uv sync --frozen --extra dev --python ${{ matrix.python-version }}`；
   - 不在 CI 中自动运行 `uv lock`，避免 CI 静默修改依赖解析结果。

5. **Verification**
   - 新提交触发 GitHub Actions；
   - Python 3.10/3.13 两个 job 的 dependency-install step 都必须成功使用 frozen lock；
   - Ruff 可以继续失败并由 `P1-04` 处理；dependency-install 失败则本任务不能 DONE。

6. **Task handoff**
   - 更新 `docs/TASKS.md` 为 DONE，并记录 lockfile commit + CI run/job 证据；
   - 下一任务为 `P1-04` Ruff。

## Acceptance criteria

```text
uv.lock committed = yes
lock generated by uv resolver = yes
uv lock consistency check = pass
CI uses --frozen = yes
Python 3.10 frozen dependency install = pass
Python 3.13 frozen dependency install = pass (compatibility target)
```

## Stop / blocked conditions

将 `P1-03` 标记为 `BLOCKED` 而不是伪造结果，如果：

- 所有可用执行环境都无法访问包索引，且无法从 CI artifact 获取 resolver 输出；
- 当前依赖约束不可解析，需要改变项目依赖策略；此时先记录 resolver 冲突，单独评审依赖变更；
- GitHub Actions 无法上传/下载生成的 lock artifact 且本地也无法解析。
